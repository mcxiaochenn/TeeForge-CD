# 可复用踩坑记录

## 2026-09-07：Android Shell 换行必须在源码和产物双重门禁

- 范围：Windows 工作树、xtask 打包和 Android 模块脚本。
- 现象：Git 索引是 LF，但工作树和待打包脚本可能是 CRLF 或混合换行，导致 Android `sh` 在子命令返回后无法可靠执行状态汇总。
- 错误假设：仓库对象中的换行正确就代表复制到模块包的工作树文件也正确。
- 根因：Windows `core.autocrlf` 会改变工作树字节，而打包流程按字节复制脚本且未复核 ZIP 内容。
- 正确处理：使用 `.gitattributes` 固定 `*.sh` 为 LF，并在源码、暂存目录和最终 ZIP 三处拒绝 `\r`。
- 验证方式：xtask 单元测试覆盖非法换行，`verify` 检查源码，`package` 检查暂存目录和 ZIP。
- 防止复发：新增 Shell 文件必须进入统一扩展名规则，不以本地编辑器显示效果代替字节检查。
- 状态：已修复，待 CI 和设备侧继续验证。

## 2026-09-07：长操作必须输出可区分的终态

- 范围：目标应用配置更新和用户可见日志。
- 现象：界面停留在“正在获取已安装包列表”，正常无变化也容易被误认为进程异常结束；重复渲染还会累积结构分隔空行。
- 错误假设：`更新 0 个配置` 足以表达成功，且视觉等价的文本一定能保持字节幂等。
- 根因：更新函数只返回空成功值，缺少跳过、无变化和已更新的结构化结果；受管区块分隔符未规范化。
- 正确处理：用穷举结果类型表达终态，逐后端输出状态并统一记录最终结果；渲染时移除并规范化工具自己的单个分隔空行。
- 验证方式：本地测试覆盖新增、卸载、用户区域归属、无变化、无后端、双后端、空列表和命令失败。
- 防止复发：任何先输出“开始”的长操作都必须在所有成功分支输出唯一终态，并为连续执行两次增加幂等测试。
- 状态：已修复，待设备侧继续验证。

## 2026-09-02：Linux ZIP 不能用 tar 检查

- 范围：xtask 跨平台模块打包。
- 现象：Linux 四 ABI 和 WebUI 都构建成功，但 ZIP 复核报告缺少 `.sha256`。
- 错误假设：默认 `tar -tf` 能读取所有平台创建的 ZIP。
- 根因：Windows 的 `tar` 可处理该归档，而 Linux GNU tar 不负责 ZIP 目录读取。
- 正确处理：Windows 使用 `tar -tf`，Linux/macOS 使用 `unzip -Z1`。
- 验证方式：远端 CI 的 Four-ABI package、Dev Build 和 Artifact 上传均成功。
- 防止复发：跨平台归档检查必须按主机工具能力分支，并在 CI 实跑验证。
- 关联提交：`4f9ba5c`。
- 状态：已修复。

## 2026-08-03：公开文档不得暴露 Keybox 维护细节

- 范围：文档和 AI 上下文管理。
- 现象：公开文档可能让不了解上下文的维护者直接复现私密解码流程。
- 错误假设：把完整维护链路写入架构文档便于所有人查阅。
- 根因：公开架构说明与私密维护手册没有分层。
- 正确处理：公开文档只写数据流、安全边界和验证要求，具体维护资料放入 Git 忽略的 `docs/private/`。
- 验证方式：私密文件被 Git 忽略，公开索引不包含算法、密钥或派生细节。
- 防止复发：新增文档前先判断内容是否属于公开架构、内部运维或私密维护。
- 关联提交：`a7fd758`、`fc25eea`。
- 状态：持续遵守。

## 2026-08-03：下载非空不代表响应有效

- 范围：Keybox 下载和 CDN 同步。
- 现象：非空 HTTP 404 响应可能被当作有效数据继续解码。
- 错误假设：只要下载结果非空就可以进入解码流程。
- 根因：未同时检查真实 HTTP/进程退出状态和内容格式。
- 正确处理：检查下载器退出码、大小上限和 `AndroidAttestation` 内容标记。
- 验证方式：无效响应 fixture 被拒绝，失败时保留旧文件。
- 防止复发：所有外部下载都必须做状态、大小和格式三重检查。
- 关联提交：`ddee09c`。
- 状态：已修复。

## 2026-09-06：兼容项目名称相近不代表配置契约相同

- 范围：Tricky Store、TEESimulator-RS、TEESimulator 的目标应用和 Keybox 同步。
- 现象：三个项目曾被当作共享 `target.txt` 处理，全量覆盖会丢失模式、Keybox 分段或 JSON profile 设置。
- 错误假设：项目名称和用途相近即可复用同一目标文件及写入策略。
- 根因：上游配置路径、归属语法和用户可编辑字段不同，且 TEESimulator 已迁移到 `config.json`。
- 正确处理：一次扫描后按真实存在的后端分别渲染；`target.txt` 使用受管区块，TEESimulator 使用带管理标记的独立 profile；所有目标和 Keybox 写入均先验证、再原子事务提交。
- 验证方式：Rust 单元测试覆盖迁移、保留用户区、profile 冲突、未知字段、双后端回滚和无后端成功路径；设备端仍需按路线图逐项验收。
- 防止复发：新增兼容项目时先核对固定版本的配置 schema、路径、归属约束和热加载机制，不以模块名称推断文件契约。
- 状态：自动化已覆盖，真机待验收。

## 2026-07-14：Android 工具和权限不能凭桌面环境假设

- 范围：模块脚本、设备兼容性和权限。
- 现象：设备可能没有 `openssl`，递归权限设置可能覆盖二进制执行权限。
- 错误假设：桌面 Linux 工具和修改前的文件权限会在 Android 安装器中保持可用。
- 根因：Android 用户空间精简，Magisk 安装阶段会重新设置权限。
- 正确处理：使用 Rust `sha2`/toybox `sha256sum`，并在 `set_perm_recursive` 后重新设置可执行权限。
- 验证方式：四 ABI 构建和安装脚本静态检查；真机结果仍需单独记录。
- 防止复发：涉及设备命令或权限时先查目标环境，再写兼容回退。
- 关联记录：`docs/history/2026-07-14-retrospective.md`。
- 状态：持续遵守。

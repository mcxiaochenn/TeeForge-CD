# TeeForge-CD README 规范

本规范用于维护仓库根目录的用户文档。`README.md` 首要服务于准备安装和使用 TeeForge-CD 的设备用户，其次才是模块维护者与贡献者。AI 协作规则、详细架构和过程记录不属于用户 README。

## 阅读目标

README 应让首次访问仓库的用户在较短时间内确认：

1. 这个模块解决什么问题，不能解决什么问题。
2. 自己的 Android、Root 实现和 ABI 是否受支持。
3. 还需要安装或关闭哪些组件。
4. 应从哪里下载稳定包，以及怎样安装。
5. 安装后如何确认模块正常工作。
6. 出现问题时如何恢复、收集日志和反馈。

## 术语与判断标准

- **首屏**：从一级标题到第一个二级标题之前的内容，不按具体设备像素或浏览器高度计算。
- **稳定版**：由正式 Release 流程发布、面向普通用户且不是 prerelease 的模块包。
- **测试版**：Dev、Canary、prerelease 或 CI Artifact；即使构建成功，也不能称为稳定版。
- **主要第三方组件**：安装包实际携带、运行时必须依赖，或会影响许可证、兼容性和用户操作的第三方内容。
- **需要拆分的长内容**：只面向开发者，或单节包含超过 12 个条目、2 个以上大段代码示例的说明。根 README 仍需保留用户完成判断和操作所需的摘要。

首屏必须展示所有实际存在且会阻止安装、导致冲突或改变风险判断的依赖和限制；“必要依赖、适用边界或高风险条件”不是三选一。

## 语言与表达

- `README.md` 是中文权威主文；需要英文说明时使用独立的 `README_EN.md`，不在同一文件中逐段重复两种语言。
- 如果英文版存在，功能、兼容性、安装、风险和下载事实必须与中文版在同一变更中同步；本规则由提交者和审查者人工检查，本轮不依赖 CI 强制。
- 英文版是可选项；仓库尚未提供 `README_EN.md` 时，普通 README 更新不自动要求新建英文版。
- 专业、克制、事实优先。首屏最多保留一句简短口号，其余内容直接说明能力、限制和操作结果。
- 不连续使用反问，不贬低其他项目，不写无法验证的最高级、绝对化兼容承诺或安全宣传。
- 不把混淆、隐藏实现或增加分析成本描述为安全保证。
- 定量声明必须有当前代码、测试或产物证据；容易变化的版本、体积、数量和状态优先链接到稳定来源。

## 必选内容

章节标题可以按上下文微调，但顺序应遵循用户从判断到安装、验证和恢复的路径。

### 1. 首屏

必须包含：

- 项目名称。
- 一句话事实性定位。
- 可选的一句短口号。
- 必要依赖、适用边界或高风险条件的醒目提示。
- 稳定版本的官方下载入口。

徽章不是必需项。使用时只保留与 Release、构建状态或许可证直接相关且来自官方数据源的徽章，不用装饰性或无法核验的动态数字占据首屏。

### 2. 核心功能

- 从用户获得的结果描述功能，而不是罗列内部函数、文件或实现技巧。
- 每项只说明一个主要结果；详细机制链接到项目文档。
- 已有边界必须同时说明，例如依赖其他模块、仅属于弱化处理或不能保证通过外部检测。

### 3. 兼容性与前置条件

至少覆盖：

- 最低 Android/API 要求。
- 支持的 Magisk、KernelSU、APatch 范围及必要开关。
- 支持的 ABI。
- 必装依赖、互斥组件和已知限制。
- 安装前需要备份或准备的恢复方式。

兼容性必须以当前安装脚本、构建矩阵和实际验收结果为准。自动化构建与真机验收分开描述，不能用构建成功代替设备兼容结论。

### 4. 下载与安装

- 稳定 Release 是普通用户的默认入口。
- Dev、Canary 或 CI Artifact 必须单独标明测试性质、适用人群和风险，不能与稳定版并列成无差别选择。
- 项目尚无稳定版时，首屏必须明确写“尚无稳定版”，只能把 prerelease 或测试产物作为测试入口，不能将其改称稳定版。
- 只链接项目控制的官方发布位置；不要让用户把 GitHub 源码归档误当成模块安装包。
- 安装步骤写明使用哪个 Root 管理器入口、是否需要重启、安装过程中有哪些选择，以及默认行为。
- 若某种安装方式不受支持，应在步骤前明确说明。

TeeForge-CD 的渠道定义为：GitHub 正式 Release 及稳定 `updateJson` 指向稳定渠道；`dev.yml` 生成的包、page 分支 dev 目录和 GitHub Actions Artifact 均属于测试渠道；项目没有声明 Canary 渠道时不要自行添加。

### 5. 安装后验证

至少给出一种普通用户可以完成的验证路径，并说明：

- 正常时应看到的模块状态、描述、输出或目标文件结果。
- 哪些提示表示操作失败或功能未启用。
- 自动化能证明什么，仍需真机确认什么。

不能只以“已刷入”或“已经重启”作为成功标准。

### 6. 基础使用与配置

- 只保留多数用户真正需要的命令、WebUI 入口和配置项。
- 命令示例应可直接复制，并说明是否需要 Root、工作目录或重启。
- 完整 CLI、配置键和开发参数较长时链接到 `docs/`，避免根 README 变成参考手册。
- 配置默认值、保存位置和升级保留行为必须与当前实现一致。

### 7. 更新、卸载与恢复

说明：

- 稳定更新的入口和配置是否保留。
- 正确卸载方式及是否需要重启。
- 模块导致异常启动或功能异常时的禁用、回滚或安全模式路径。
- 哪些操作可能删除用户数据或配置。

恢复说明必须来自当前支持的 Root 管理器行为或项目脚本，不能凭桌面系统经验推断 Android 行为。

### 8. 故障排查与反馈

提交问题前至少要求提供：

- TeeForge-CD 版本与下载渠道。
- Android 版本、设备 ABI、Root 实现及版本。
- 相关依赖模块版本。
- 可复现步骤、期望结果和实际结果。
- 项目规定的日志或安装输出；上传前移除隐私信息。

常见问题只保留高频且答案稳定的项目。复杂排查流程应链接到独立文档，支持渠道要明确区分问题反馈与社区讨论。

### 9. License、来源与致谢

- 链接仓库许可证并使用一致的许可证名称。
- 标明上游项目、主要第三方组件和必要归属。
- 不把第三方项目描述为官方合作方，除非存在可核验授权。

## 可选章节

按项目实际需要选择，不为空模板补内容：

- WebUI 截图或操作演示。
- 详细兼容矩阵。
- FAQ。
- 完整 CLI 或配置参考。
- 从源码构建。
- 项目结构与架构。
- 贡献指南、翻译说明或安全政策。

面向开发者的构建、目录和架构内容应排在用户路径之后。符合“需要拆分的长内容”标准时，优先放入现有 `docs/project/`、`docs/development/` 或 `docs/operations/`，README 只保留摘要和入口。

## 推荐骨架

以下骨架用于检查覆盖面，不要求机械复制标题：

```markdown
# TeeForge-CD

一句话定位。

> [!WARNING]
> 最重要的依赖、限制或风险。

[下载稳定版](https://github.com/<owner>/<repo>/releases/latest)

## 功能

## 兼容性与前置条件

## 下载与安装

## 安装后验证

## 使用与配置

## 更新、卸载与恢复

## 故障排查与反馈

## License 与致谢
```

## Markdown 与链接

- 每份 README 只使用一个一级标题，标题层级不得跳级。
- 命令、配置和日志使用带语言标识的 fenced code block；占位符应明确，不把提示符一起复制给用户。
- 图片必须提供能表达用途的替代文本；没有实际 UI 或操作价值时不添加截图。
- 仓库内文档使用相对链接；外部链接使用描述性文字，不堆裸 URL。
- 表格只用于对比关系，控制列数并保证手机端仍可阅读；顺序操作使用编号列表。
- `> [!NOTE]`、`> [!WARNING]` 等提示块只承载会影响选择、数据或设备安全的信息，不滥用。
- 链接稳定页面而非临时 Artifact；必要的 Dev 下载必须明确其生命周期和不可作为稳定回退来源。
- 当前仓库没有 README 专用 lint 或 CI 门禁。提交者需运行 `git diff --check`，逐个解析本次新增或修改的相对链接，并在可联网环境打开变更涉及的外部下载和支持链接；审查者复核结果。

## 事实来源与安全边界

README 中的事实按以下来源复核：

| 事实 | 首要来源 | 辅助说明 |
|---|---|---|
| 模块身份与安装包元数据 | `module/module.prop`、xtask 构建注入 | 稳定版本手写来源见 `crates/teeforge/Cargo.toml` |
| Android、ABI 与安装行为 | `module/customize.sh`、`xtask/src/main.rs` | 用户说明见 `docs/operations/INSTALLATION.md` |
| CLI 与配置行为 | `crates/teeforge/src/` | 项目说明见 `docs/project/OVERVIEW.md` 和 `ARCHITECTURE.md` |
| 构建、下载与发布渠道 | `.github/workflows/ci.yml`、`dev.yml`、`release.yml` | 渠道说明见 `docs/development/BUILD_AND_RELEASE.md` |
| 许可证与第三方归属 | `LICENSE`、依赖清单和被打包文件 | 不凭 README 旧文本推断 |

来源冲突时，以当前源码、脚本和 workflow 为实现事实，实际产物检查为构建事实，带日期和环境的设备记录为真机事实；先修正对应项目文档，再更新 README。没有覆盖到的设备或 ABI 必须标为未验收，不能从其他环境外推。

README 不得包含私密 Keybox 维护机制、密钥信息、可复现的内部处理流程，或指引读者绕过私密资料边界。公开说明只描述用户可见的数据流、输入要求、失败行为和安全边界。

## 更新触发条件

以下任一事项变化时，必须检查并按需同步 README；英文版存在时一并同步：

- 用户可见功能、公共命令、配置入口或默认行为。
- Android、Root 实现、ABI、依赖或冲突条件。
- 安装、升级、卸载、恢复或配置保留行为。
- 稳定版、Dev 版、CDN、Release 或支持渠道。
- 用户需要了解的风险、安全边界或验收状态。
- 项目名称、许可证、上游来源或主要第三方组件。

纯内部重构且没有改变用户行为时不制造 README 改动。

## 提交前检查

- [ ] 首屏能回答用途、依赖、稳定下载和关键限制。
- [ ] 功能描述对应当前实现，没有无证据数字或绝对承诺。
- [ ] Android、Root 实现、ABI 和依赖与安装脚本一致。
- [ ] Release 与 Dev 下载明确区分。
- [ ] 安装步骤包含验证结果和失败判定。
- [ ] 更新、卸载和恢复路径明确，不隐瞒数据影响。
- [ ] 问题反馈说明日志、环境和复现信息要求。
- [ ] 没有公开私密维护内容、凭据、设备信息或敏感日志。
- [ ] 中文版与英文版的当前事实一致。
- [ ] 内部链接有效，外部链接指向项目或上游官方来源。
- [ ] README 没有复制完整开发文档或 AI 指引。
- [ ] `git diff --check` 和 Markdown 链接检查通过。

## 调研基线

调研日期：2026-09-05。以下只记录可复用的信息组织方式，不复制项目文案，也不把当时版本和状态当作 TeeForge-CD 的事实。

| 样本 | 采用的做法 | 不直接采用的做法 |
|---|---|---|
| [ReZygisk](https://github.com/PerformanC/ReZygisk/blob/main/README.md) | 分离多语言、区分 Release/Debug、安装后验证 | 不把项目立场或内部实现放在用户主路径前部 |
| [LSPosed](https://github.com/LSPosed/LSPosed) | 简洁的要求、安装、下载、反馈与许可证路径 | 不依赖外部 Wiki 才能完成最基本安装判断 |
| [Play Integrity Fork](https://github.com/osm0sis/PlayIntegrityFork) | 明确不同 Root 环境和系统化排障 | 复杂配置不全部堆在根 README |
| [TEESimulator](https://github.com/JingMatrix/TEESimulator/blob/dev/README.md) | 要求、安装、配置、恢复和构建边界清晰 | 开发结构只在确有贡献者需求时保留 |
| [ACC](https://github.com/VR-25/acc) | 风险、前置条件、快速开始和深入排障完整 | 不采用百科式超长目录作为默认结构 |
| [ReVanced Magisk Module](https://github.com/j-hc/revanced-magisk-module/blob/main/README.md) | 根 README 保持简短，高级配置链接到独立文档 | 不用单行简写代替必要的兼容性和恢复说明 |
| [Targeter](https://github.com/Astoritin/Targeter) | 操作步骤与注意事项直接对应用户行为 | 不采用同文件逐段双语复制 |
| [KernelSU Modules Repo 示例](https://github.com/KernelSU-Modules-Repo/org.kernelsu.example) | README 作为模块详情页，Release 承载版本变更 | 不在 README 重复动态版本状态 |

Magisk 和 KernelSU 模块语义以 [Magisk 官方模块指南](https://github.com/topjohnwu/Magisk/blob/master/docs/guides.md)和 [KernelSU 官方模块指南](https://github.com/tiann/KernelSU/blob/main/website/docs/guide/module.md)为准；社区 README 只作为信息架构参考。

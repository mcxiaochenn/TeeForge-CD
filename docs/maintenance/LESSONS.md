# 可复用踩坑记录

## 2026-10-19：格式标记不能代替完整数据及落盘校验

- 现象：用户报告手机安装后的文件格式损坏，主机端当前上游和 CDN 内容一致且可解析，设备故障尚未复现。
- 根因边界：旧入口仅检查文本标记，会放过结构或 PEM 编码损坏；这是已确认的校验缺口，不是已确认的设备故障根因。
- 正确处理：发布和模块共用格式校验，使用合成材料验证跨语言处理、安装及回读；写入失败恢复本轮文件、备份和选择。
- 验证方式：覆盖畸形结构、数量不符、字段缺失、无效编码、伪造标记、回读损坏及配置保存失败。
- 防止复发：构建成功、格式有效、后端可用和设备验收分别报告；真实私密材料不入测试资源、日志或提交。

## 2026-10-19：锁文件缺少其他平台可选依赖也会阻断 npm ci

- 现象：Windows 四 ABI 打包在 npm ci 阶段报告缺少 Rollup 的 Darwin x64 可选包。
- 根因：锁文件缺少已锁定 Rollup 版本声明的平台包条目，普通增量构建未暴露问题。
- 正确处理：仅补齐缺失条目，保留其他依赖及版本；不提交安装工具附带的无关锁文件清理。
- 验证方式：重新执行使用 npm ci 的完整打包及产物验证。
- 防止复发：以干净依赖安装作为打包门禁，不能仅以已有 node_modules 下的构建成功判断依赖完整。

## 2026-10-18：同一个帧不要解析两次，也不要假设只有一种帧

- 范围：设备端 RKP 签发（`crates/teeforge/src/rkp/`）。
- 现象：小米 17 Pro 上 `--rkp-issue` 报 `TA 响应长度无效 [invalid payload length]`，`--json` 信封里只有 `message`，没有 `stage` 与 `raw`。
- 根因有两层：
  1. `ta::request` 内部已经调用 `response_payload` 返回 payload，`worker` 把它 base64 回传，编排层又对 payload 调用了一次同一个函数，把 CBOR 的前 8 字节当成 `[status][len]`。
  2. 厂商 `send_cmd` 的响应布局并非只有 `[status][len][payload]` 一种；长度字段不符合假设时，第一次解析就会失败。
  另外 `worker` 用 `error.to_string()` 传错误，跨进程后 `stage/code/hint/raw` 全部丢失，界面上只剩一句中文，无法判断是哪一层出的问题。
- 正确处理：`ta` 层只调用、只返回原始缓冲区；`protocol::decode_frame` 是唯一帧解析入口，按五种候选布局依次切片，并要求业务解析（`unwrap_csr`）成功才采纳；worker 回执改为结构化错误对象，并带回 `head_hex`、`written`、`status_le`。
- 验证方式：五种布局各一个夹具，加上哨兵未写入、负 status、不可解析三类错误分支，全部在主机侧断言；`--json` 信封里必须能看到 `stage` 与 `raw`。
- 防止复发：一个数据格式只允许有一个解析入口；跨进程传递错误必须传结构，不传 `Display` 字符串；对"长度字段"这类自洽但语义可变的数据，用业务结构判定而不是数值范围。
- 状态：已修复，真机待验收。

## 2026-10-18：WebUI 溢出先查负外边距，再查视口高度

- 范围：`webroot/` 的全局布局。
- 现象：小米 17 Pro 上页面左右上下都能拖动，边缘内容被裁。
- 根因：导航栏写了 `-mx-4 px-4`，但它是 `.shell` 的直接子元素、而 `.shell` 没有 `px-4`，负外边距让块级自动宽度增加 32px，直接撑出横向滚动；纵向则是 `body` 同时设了 `min-height: 100vh` 与 `100dvh`，在 KernelSU 的 WebUI 容器里 `100vh` 取的是最大视口高度，比 iframe 实际高度大一截。
- 正确处理：负外边距只在"父容器确实有对应内边距"时使用；`body` 改为 `min-height: 100%` 并由内容决定高度；横向兜底用 `overflow-x: clip`（不创建滚动容器，不破坏 sticky），旧 WebView 用 `@supports` 退回 `hidden`；viewport 加 `user-scalable=no`。
- 验证方式：用同源 iframe 逐页测量 `scrollWidth - clientWidth`、遍历元素找越界项、滚动后确认 `header` 的 `top` 仍为 0。不要用 `--window-size` 直接截图判断，窗口尺寸与视口尺寸不等价，截图会带缩放伪影。
- 防止复发：新增固定宽度或负边距前先确认父容器的 padding；不用 `vh` 表达"铺满一屏"；截图结论必须与几何测量互相印证。
- 状态：已修复，真机待验收。

## 2026-10-17：设备端 RKP 不能把“文件存在”当成 ABI 兼容

- 范围：设备端 RKP 签发（`crates/teeforge/src/rkp/`）。
- 现象：上游 Duck-ToolBox 在 OnePlus PJX110 / Android 16 上收到 TA 状态 `-18`，未签发成功；社区在小米 17 Pro 等机型有成功案例。
- 错误假设：`/vendor/lib64/libkeymasterdeviceutils.so` 与 `/dev/smcinvoke` 存在，就能安全调用 `send_cmd`。
- 根因：厂商 `KeymasterUtils` 的对象布局、符号与固件实现随版本变化；前置检查只能证明文件存在，不能证明 ABI 兼容或服务端接受。
- 正确处理：TA 调用放在隔离子进程（30 秒超时后 kill 并回收），失败按 `rkp_mode` 回退远程；每步失败原因写入日志；只有设备签发且安装成功后才写复用标记。
- 验证方式：主机侧协议、证书链、缓存与回退路径单元测试通过，四 ABI 编译通过；真机签发与错误码仍待验收。
- 防止复发：涉及厂商库时不在主进程直接 dlopen；不以存在性检查代替真实调用结论；自动化结果与真机结果分开记录。
- 状态：自动化已覆盖，真机待验收。

## 2026-09-14：OMK 配置替换需要保留元数据与真实渲染快照

- 范围：OMK injector.toml 作用域与多目标配置事务。
- 现象：上游活动配置使用 keystore 用户身份和 0600 权限；只原子替换内容会改变文件归属，桌面内容测试无法证明服务仍可读取。
- 根因：普通临时文件不会自动继承旧文件的 UID/GID、mode 或 Android SELinux 标签。另外，渲染完成后重新读取原文件作为事务基线，会掩盖读取与渲染之间发生的外部修改。
- 正确处理：OMK 使用限制权限的同目录临时文件，准备原元数据成功后才替换；使用 injector.toml.teeforge.bak 专用备份，回滚保留元数据。PendingUpdate 持有渲染使用的原始字节，提交前核对；回滚时发现外部修改则拒绝覆盖并报告。
- 验证方式：Windows/Linux 测试覆盖原始快照冲突、后续目标失败回滚、备份不重复刷新；Linux 验证 UID/GID、0600 权限与失败临时文件清理。Android SELinux 和 OMK 热加载仍待真机验收。
- 防止复发：新增配置后端时核对上游文件创建者、权限、配置语法及热加载契约；文件事务成功不等于多个服务同时切换。
- 状态：自动化已覆盖，真机待验收。

## 2026-09-07：Android Shell 换行必须在源码和产物双重门禁

- 范围：Windows 工作树、xtask 打包和 Android 模块脚本。
- 现象：Git 索引是 LF，但工作树和待打包脚本可能是 CRLF 或混合换行，导致 Android `sh` 在子命令返回后无法可靠执行状态汇总。
- 错误假设：仓库对象中的换行正确就代表复制到模块包的工作树文件也正确。
- 根因：Windows `core.autocrlf` 会改变工作树字节，而打包流程按字节复制脚本且未复核 ZIP 内容。
- 正确处理：使用 `.gitattributes` 固定 `*.sh` 为 LF，并在源码、暂存目录和最终 ZIP 三处拒绝 `\r`。
- 验证方式：xtask 单元测试覆盖非法换行，`verify` 检查源码，`package` 检查暂存目录和 ZIP。
- 防止复发：新增 Shell 文件必须进入统一扩展名规则，不以本地编辑器显示效果代替字节检查。
- 状态：已修复，待 CI 和设备侧继续验证。

## 2026-09-07：长操作必须输出可区分的终态

- 范围：目标应用配置更新和用户可见日志。
- 现象：第一轮修复后，设备日志仍可能停留在“正在获取已安装包列表”；正常无变化也曾容易被误认为进程异常结束。
- 错误假设：只补齐更新函数的成功终态，就能覆盖外部命令永不返回或输出失控的情况。
- 根因：内部结果已区分跳过、无变化和更新，但包管理命令仍使用无超时、无 stdout 上限的完整缓冲调用。
- 正确处理：保留穷举终态，并为包管理命令增加并发管道读取、30 秒超时、4 MiB stdout 上限和有界 stderr；命令成功返回后再记录解析边界。
- 验证方式：本地测试覆盖新增、卸载、用户区域归属、无变化、无后端、双后端、命令失败、超时、输出超限和失败不改文件。
- 防止复发：任何先输出“开始”的外部命令都必须有资源边界和失败终态；连续执行还要覆盖幂等结果。
- 状态：本地自动化已修复，待设备侧继续验证。

## 2026-09-02：Linux ZIP 不能用 tar 检查

- 范围：xtask 跨平台模块打包。
- 现象：Linux 四 ABI 和 WebUI 都构建成功，但 ZIP 复核报告缺少 `.sha256`。
- 错误假设：默认 `tar -tf` 能读取所有平台创建的 ZIP。
- 根因：Windows 的 `tar` 可处理该归档，而 Linux GNU tar 不负责 ZIP 目录读取。
- 正确处理：Windows 使用 `tar -tf`，Linux/macOS 使用 `unzip -Z1`。
- 验证方式：远端 CI 的 Four-ABI package、Dev Build 和 Artifact 上传均成功。
- 防止复发：跨平台归档检查必须按主机工具能力分支，并在 CI 实跑验证。
- 关联提交：`4f9ba5c`。
- 状态：已修复。

## 2026-08-03：公开文档不得暴露 Keybox 维护细节

- 范围：文档和 AI 上下文管理。
- 现象：公开文档可能让不了解上下文的维护者直接复现私密解码流程。
- 错误假设：把完整维护链路写入架构文档便于所有人查阅。
- 根因：公开架构说明与私密维护手册没有分层。
- 正确处理：公开文档只写数据流、安全边界和验证要求，具体维护资料放入 Git 忽略的 `docs/private/`。
- 验证方式：私密文件被 Git 忽略，公开索引不包含算法、密钥或派生细节。
- 防止复发：新增文档前先判断内容是否属于公开架构、内部运维或私密维护。
- 关联提交：`a7fd758`、`fc25eea`。
- 状态：持续遵守。

## 2026-08-03：下载非空不代表响应有效

- 范围：Keybox 下载和 CDN 同步。
- 现象：非空 HTTP 404 响应可能被当作有效数据继续解码。
- 错误假设：只要下载结果非空就可以进入解码流程。
- 根因：未同时检查真实 HTTP/进程退出状态和内容格式。
- 正确处理：检查下载器退出码、大小上限和 `AndroidAttestation` 内容标记。
- 验证方式：无效响应 fixture 被拒绝，失败时保留旧文件。
- 防止复发：所有外部下载都必须做状态、大小和格式三重检查。
- 关联提交：`ddee09c`。
- 状态：已修复。

## 2026-09-06：兼容项目名称相近不代表配置契约相同

- 范围：Tricky Store、TEESimulator-RS、TEESimulator 的目标应用和 Keybox 同步。
- 现象：三个项目曾被当作共享 `target.txt` 处理，全量覆盖会丢失模式、Keybox 分段或 JSON profile 设置。
- 错误假设：项目名称和用途相近即可复用同一目标文件及写入策略。
- 根因：上游配置路径、归属语法和用户可编辑字段不同，且 TEESimulator 已迁移到 `config.json`。
- 正确处理：一次扫描后按真实存在的后端分别渲染；`target.txt` 使用受管区块，TEESimulator 使用带管理标记的独立 profile；所有目标和 Keybox 写入均先验证、再原子事务提交。
- 验证方式：Rust 单元测试覆盖迁移、保留用户区、profile 冲突、未知字段、双后端回滚和无后端成功路径；设备端仍需按路线图逐项验收。
- 防止复发：新增兼容项目时先核对固定版本的配置 schema、路径、归属约束和热加载机制，不以模块名称推断文件契约。
- 状态：自动化已覆盖，真机待验收。

## 2026-07-14：Android 工具和权限不能凭桌面环境假设

- 范围：模块脚本、设备兼容性和权限。
- 现象：设备可能没有 `openssl`，递归权限设置可能覆盖二进制执行权限。
- 错误假设：桌面 Linux 工具和修改前的文件权限会在 Android 安装器中保持可用。
- 根因：Android 用户空间精简，Magisk 安装阶段会重新设置权限。
- 正确处理：使用 Rust `sha2`/toybox `sha256sum`，并在 `set_perm_recursive` 后重新设置可执行权限。
- 验证方式：四 ABI 构建和安装脚本静态检查；真机结果仍需单独记录。
- 防止复发：涉及设备命令或权限时先查目标环境，再写兼容回退。
- 关联记录：`docs/history/2026-07-14-retrospective.md`。
- 状态：持续遵守。

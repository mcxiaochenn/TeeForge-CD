# 文档维护规则

## 每轮结束检查

每轮工作结束前判断：

1. 是否改变架构、公共命令、配置、目录、兼容性或安全边界。
2. 是否改变构建、CI、安装或发布流程。
3. 是否完成、取消或新增待验收事项。
4. 是否发现新的平台差异、错误假设、失败模式或恢复方法。
5. 是否新增、移动或废弃文档，导致索引需要变化。

## 更新位置

- 当前技术事实变化：更新 `docs/project/`、`development/` 或 `operations/`。
- 当前任务状态变化：更新 `ROADMAP.md`。
- 可复用的新故障经验：更新 `LESSONS.md`。
- 只属于过去阶段的过程：保留或移动到 `history/`。
- 没有文档影响：不制造无意义文档改动。

`AGENTS.md` 只保留硬规范和导航；`CLAUDE.md` 只负责跳转，不在这两个入口记录动态事实。

## 记录要求

新增经验必须说明现象、根因、正确处理、验证方式和防止复发方法，不能只写“以后注意”。

最终回复必须说明：

```text
文档检查：已更新 <文件和原因>
```

或：

```text
文档检查：无需更新，原因是本轮没有改变项目事实或产生可复用经验。
```

## 隐私边界

Keybox 私密维护文件只允许在用户授权的本地维护任务中读取。不得复制到公开 docs、Git 提交、日志、Issue、最终回复或自动化输出。
